Behaviour
---------
- No success before the server confirms; the vehicle is never shown AVAILABLE optimistically (tested with a held
  response). Double click on the confirm button sends one request (button disabled while pending; DB shows one
  inspection per unit).
- Dispositions offered = server's allowedDispositions; PASS disabled with an explanation when no checklist applies;
  a held vehicle offers only Reject, with the OQ-31 note; AVAILABLE/REJECTED vehicles: no form.
- Client validation mirrors the contract (outcome per item, FAIL note, PASS without failures, HOLD/REJECT notes and
  >= 1 evidence file); the server re-checks and its 422 fields are shown on the form and in the dialog.
- Evidence uploads carry the unit's location; only files the server confirmed are listed; upload errors stay visible
  and do not count as evidence.
- Read-only users see history and status; recording needs vehicle_units.pdi.record; without vehicle_units.view the
  pages show access denied and call no PDI endpoint.

Bug found and fixed during the browser test
-------------------------------------------
After a successful record, the hook-level onSuccess awaited the overview refetch; the new status re-keyed (unmounted)
the form, and TanStack Query skipped the per-call mutate() onSuccess, so the "recorded" banner never appeared (Vitest
passed by timing). Fixed by using mutateAsync().then(...) in the confirmation dialog.
