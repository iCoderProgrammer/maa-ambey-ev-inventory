Permissions (UI gating only; the server decides)
------------------------------------------------
- stock.parts.view: Stock card + history. Without it the panel is not shown.
- stock.parts.receive + suppliers.view: Receive stock (supplier must be chosen). Without suppliers.view the
  button is replaced by a note.
- stock.parts.issue: Issue stock.
- Supplier names in history are null from the server without suppliers.view; the UI says so.
- No grants were added anywhere except test-only grants on the disposable database (container e04f-pg).

Idempotency / safety
--------------------
- One frozen action (body + UUID key) per decision; the same unchanged body in the same dialog reuses the key;
  any changed field makes a new key. Mutations retry:false.
- Network failure, timeout or 5xx: "may or may not have been recorded"; the button becomes "Send again
  unchanged" (same key). Server replay is counted once (verified in Playwright with a lost response).
- Double submit guarded (isPending); one POST.
- Success shown only after the server answer validates (type, SKU, location, balance belongs to movement).
- INSUFFICIENT_STOCK: form kept, balances refreshed, "Nothing was changed".
- Quantities handled as text/BigInt thousandths (no floating point); > 0, up to 9 digits and 3 decimals.
- UOM shown read-only from the SKU (no conversion, OQ-34). SERIAL SKUs: no forms, note shown (OQ-38).
  Archived SKUs: no forms.
