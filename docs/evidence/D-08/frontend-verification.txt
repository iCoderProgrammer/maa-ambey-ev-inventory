Behaviour
---------
List: server search (unit number, chassis/frame, motor, battery, charger; 350 ms debounce), filters status,
saleable, brand -> model -> variant (catalogue API; disabled without catalogue.view), location (the caller's
assigned locations from /me), supplier (suppliers API; disabled without suppliers.view), received from/to,
min/max days in stock, sort (server orders). All filters in the URL, page reset on change, "Clear filters".
Server pagination. Desktop table / phone card list (ResponsiveTable). Cost column only with
vehicle_units.cost.view, hidden cost shown as "Recorded (not visible to you)". Every non-AVAILABLE status is
marked "Not saleable"; no reserve/sell/transfer/status action anywhere. Colour: no filter/column (not stored).
States: skeleton, empty inventory, no results, invalid filter (server field messages), error + retry,
403 access denied, 401 -> sign-in, no permission (no request sent).
Detail: header with status and saleable/not-saleable reason; Vehicle (unit number, internal ID, brand, model,
variant, status, location, days in stock, cost only when the server sends it); Identifiers; Procurement
(supplier, PO and GRN links only with their view permissions, supplier reference, received, registered by);
Documents (server-filtered, private download via attachment link; "no permission" when documentsHidden);
PDI (the shared D-06 InspectionHistory + link to the PDI screen); Movement history (read-only ledger, oldest
first, paginated, source links: GRN, PDI inspection). Back link keeps the list filters. QR: none (D-09).

Bug found and fixed during this phase
-------------------------------------
- Search could drop a filter chosen while the 350 ms search pause was running (the memoised search callback
  used the first render's URL setter, so React Router rebuilt the URL from stale parameters). Fixed by calling
  the latest setter through a ref; regression test "keeps a filter chosen while a search is still pending"
  (verified to fail without the fix). Other list pages share the older pattern (not changed: out of scope).
- Observed in automation only: two filter changes within one frame (before React re-renders) can overwrite
  each other, because the shared useListParams helper builds on the last rendered URL. Not reachable by a
  person; the e2e waits for each change to render. Shared helper left unchanged (cross-feature).
