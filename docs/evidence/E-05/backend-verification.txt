Behaviour
---------
- Expected quantity/status and the balance/unit version are read by the server when a line is recorded; variance is
  computed by the database; reason required for a variance; client-sent expected/variance/status are 422.
- Create, record, submit and reject change no stock and write no movement.
- Approval (one transaction): lock count -> replay check -> status/version -> policy -> separation of duties ->
  create/lock each balance (FOR UPDATE) / lock each unit -> re-check versions (STOCK_CHANGED_SINCE_COUNT, nothing
  posted) -> one COUNT_ADJUSTMENT per parts line with a variance (trigger moves the balance) -> link line -> APPROVED
  -> audit. Vehicle discrepancies: finding only, no movement, unit unchanged.
- Separation of duties: creator, submitter, or anyone who recorded a line (also per audit history) cannot approve or
  reject: 403, audited DENIED. DB CHECK also refuses decided_by = creator/submitter.
- No threshold: every count needs an approver; without one it stays SUBMITTED (fail closed).
- Idempotency: create per creator key; approve/reject per decider key + request hash (replay 200, reused 409).
- Audit: stock_count.created/.line_recorded/.submitted/.approved/.rejected, stock_item.adjusted per movement;
  DENIED for self-decision and stock changed since count.
