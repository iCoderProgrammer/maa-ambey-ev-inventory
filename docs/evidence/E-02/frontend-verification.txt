Behaviour
---------
Timeline: server search (unit number, chassis/frame, SKU; 350 ms pause), item type (only with both view permissions),
movement type, source type, source reference (exact, on Enter/blur), recorded by (Me / a person pinned from a
link), location (the caller's /me locations), from/to date (the user's calendar days -> RFC 3339 instants, to =
start of next day), order (newest/oldest); vehicle/part pins from detail links. All in the URL, page reset on
change, Clear filters. Server paging. Desktop table / phone cards. Columns: movement + time (user's zone, seconds,
UTC offset stated), vehicle/part (linked only with vehicle_units.view / stock_items.view), status change (vehicles) or
quantity (parts), location, recorded by (You / display name), source (GRN link with goods_receipts.view, count link
with stock.adjustment.view, PDI link with the unit; "Not visible to you" when sourceHidden), View.
Detail: every ledger field, supplier (suppliers.view), reason/note, movement ID, related-movement links (this unit/SKU,
this person, this source). No edit, delete, reverse or correction control anywhere; no request other than GET.
States: skeleton, empty ledger, no results, invalid filter (server field messages), error + retry, offline, 403,
401 -> sign-in, no permission (no request), 404 detail.
Filter race: useUrlFilters applies each change on top of the latest one; regression test proves two changes in one
frame both survive (fails with the shared useListParams, which was left unchanged).
