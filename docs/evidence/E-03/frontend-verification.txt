== Behaviour ==
- Permissions: page gate stock_items.view (detail keeps heading while denied); Add/Edit need stock_items.manage; Archive
  needs stock_items.archive; supplier picker/filter/details only with suppliers.view (otherwise a note, and a PATCH never
  sends suppliers); compatibility picker only with catalogue.view; nav item hidden without stock_items.view.
- SKU code: trimmed, 1-40 of A-Z a-z 0-9 . _ / - (no spaces); duplicates in any case come back from the server as 409
  and are shown on the field; separators significant. Code and tracking mode read-only on edit, with the reason.
- UOM: free entry, format check only (1-10 letters/digits, starts with a letter), stored upper-case; hint says no
  approved list exists (OQ-34 open).
- Reorder level: up to 3 decimals for QUANTITY, whole for SERIAL (create and edit, using the stored mode); shown without
  trailing zeros.
- Suppliers: archived suppliers not offered for new links; pending ones labelled "(pending verification)"; removed rows
  are ended by the server and shown as "Ended …" history; no delete call.
- Compatibility: brand (from /brands, archived excluded) and optional model loaded per brand (/models?brandId=), so a
  model of another brand cannot be chosen; server cross-brand/archived errors mapped to the row; "staff-entered, not an
  approved manufacturer fitment" shown.
- Edit sends only changed fields; "Nothing has changed" without a request. Stale version -> reload offer, entries kept.
- Archive (SKU and category): confirmation dialog, reason required, effects listed, no reactivation; category archive
  refused by the server while it has active SKUs -> server message shown, nothing changed.
- Cache: nothing optimistic; every stock-items query invalidated after a confirmed mutation.

== Defect found in the browser test and fixed ==
Edit dialog showed the stored supplier, brand and model as empty ("Choose a supplier") because their options loaded
after the form was filled (a native select cannot show a value without its option). Fix: the selects re-attach once
their options have loaded. Regression test "shows the stored supplier, brand and model once their options have loaded"
fails without the fix and passes with it.
